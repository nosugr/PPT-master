# 01_封面

各位老师好，我是翁嘉程，今天答辩的题目是掌纹识别门禁系统。我们小组的成员还有罗志铭和李佳洋。这个系统实现了从掌纹采集、特征编码、身份匹配到 STM32 控制开锁的完整闭环。

# 02_目录

本次答辩分为四个部分。第一部分介绍项目背景和系统架构，第二部分讲解技术路线和算法原理，第三部分展示硬件连接和实际效果，最后总结系统的不足和改进方向。

# 03_章节页_项目背景

首先是项目背景与系统架构。掌纹识别是一种非接触式生物特征识别技术，我们的目标是打通从掌纹采集到门锁控制的完整链路。

# 04_掌纹识别概念

掌纹识别是通过手掌主线、皱褶和细节纹理等特征来认证用户身份的技术。与指纹、人脸、虹膜相比，掌纹具有采集方便、成本低、隐私争议小等优势。我们的系统使用普通 RGB 摄像头就能完成非接触采集。

# 05_主流算法分类

掌纹识别的主流方法分为四类：线特征方法、子空间方法、编码类方法和深度学习方法。我们选择的是 CompCode 竞争编码，因为它算法链路清晰、计算量低，适合课程设计原型。

# 06_应用场景

掌纹识别的典型应用场景包括门禁通行、考勤签到和安防核验。应用层的价值在于减少接触、降低忘带卡的风险，并且可以和日志系统联动形成可追溯的通行记录。

# 07_为什么选择掌纹识别

我们选择掌纹识别有四个原因：普通摄像头即可采集、非接触体验好、隐私争议较小、纹理特征丰富。这些特点使掌纹识别非常适合校园门禁场景。

# 08_系统架构总览

系统采用三层架构。前端交互层使用 Vue 3 和 Naive UI，算法处理层基于 Flask 和 CompCode，硬件执行层通过 STM32 控制继电器、电磁锁和反馈设备。SQLite 负责存储用户、模板和识别记录。

# 09_系统数据流

数据流从摄像头采集开始，经过 MediaPipe 手掌检测、Zhang ROI 裁剪、CLAHE 预处理、CompCode 编码，然后与模板匹配，最后通过阈值判决决定开锁或拒绝。

# 10_数据库设计

数据库使用 SQLite，包含三张表：users 存储用户信息，templates 存储 CompCode 编码和掩码数据，recognition_logs 记录每次验证的距离、阈值和结果。

# 11_章节页_技术路线

接下来进入第二部分，技术路线与算法原理。这部分是整个系统的核心，包括软件架构和掌纹识别算法的详细实现。

# 12_软件架构详解

软件采用前后端分离架构。前端是 Vue 3 单页应用，提供注册、验证和日志三个页面。后端是 Flask API，负责编排算法流程。前后端通过 RESTful API 和 JSON 数据交换。

# 13_算法流程总览

算法分为预处理链路和匹配链路。预处理包括灰度化、CLAHE 均衡化和 ROI 裁剪。匹配链路包括 Gabor 滤波、CompCode 编码、掩码归一化汉明距离和阈值判决。

# 14_手掌检测MediaPipe

手掌检测使用 Google 的 MediaPipe Hands 模型，可以实时检测 21 个手部关键点。相比早期的 HSV 颜色分割方案，MediaPipe 对光照变化和肤色差异有更好的鲁棒性。

# 15_ROI提取与Zhang坐标系

ROI 提取基于 Zhang 坐标系。我们以手腕和中指根部两个关键点建立坐标系，然后在坐标系中裁剪固定偏移区域，输出 128 乘 128 的标准化灰度图像。

# 16_数据预处理

数据预处理包括三个步骤：灰度化将 RGB 转为单通道，CLAHE 自适应对比度增强消除光照不均，高斯模糊消除高频噪声。这些预处理提升了后续编码的稳定性。

# 17_CompCode竞争编码原理

CompCode 的核心是 6 方向 Gabor 滤波。对每个像素，用 6 个方向的 Gabor 滤波器分别卷积，选择响应最强的方向，用 3 位二进制编码表示。这样就把掌纹纹理转化为方向编码特征。

# 18_模板存储与匹配逻辑

注册阶段将 CompCode 编码存入数据库。验证阶段遍历所有模板，逐一计算汉明距离，取最小距离作为匹配结果，然后进行阈值判决。

# 19_ShiftMatching与掩码归一化

由于用户每次放置手掌的位置不完全一致，我们加入正负 6 像素的 Shift Matching，在小范围内平移模板取最小距离。同时用掩码标记有效像素区域，只在有效区域内计算汉明距离。

# 20_阈值判决与开锁触发

如果匹配距离小于阈值，验证通过，发送 UNLOCK 命令开锁，绿灯亮并单响。如果距离大于阈值，验证失败，发送 FAIL 命令，红灯亮并双响。阈值基于 EER 分析选择。

# 21_数据集标定结果

数据集标定结果展示了真伪样本的距离分布。同人距离集中在左侧，异人距离集中在右侧。通过 EER、FAR、FRR 等指标分析，我们选择了合适的判决阈值。

# 22_算法复杂度与实时性

CompCode 编码耗时约 15 毫秒，单次匹配约 5 毫秒，总验证链路约 100 毫秒。相比 CNN 等深度学习方法，CompCode 仅需 CPU 就能实时运行。

# 23_端到端算法流程

端到端流程从摄像头抓帧开始，经过检测、裁剪、预处理、编码、匹配、判决，最终输出开锁或拒绝指令，总耗时约 100 毫秒。

# 24_算法关键技术总结

算法的五大关键技术是：MediaPipe 手掌检测、Zhang ROI 标准化裁剪、CompCode 竞争编码、Shift Matching 平移搜索、以及基于 EER 的阈值判决。

# 25_章节页_硬件连接

第三部分是硬件连接与结果演示。前端负责交互展示，后端完成识别与控制指令下发，STM32 驱动电磁锁和反馈设备。

# 26_硬件架构

硬件分为四层：感知层是 USB 摄像头，处理层是 PC 上的 Flask 后端，通信层是串口 UART，执行层包括 STM32、继电器、电磁锁、LED 和蜂鸣器。

# 27_硬件组件功能详解

STM32F407 主控板接收串口命令，驱动继电器和反馈设备。继电器控制 12V 电磁锁回路。LED 指示灯绿色表示成功，红色表示失败。蜂鸣器单响表示成功，双响表示失败。

# 28_串口通信协议

串口使用 ASCII 行协议，波特率 115200。命令包括 UNLOCK 开锁、OK 成功反馈、FAIL 失败反馈和 PING 健康检查。硬件抽象层提供 MockBridge 和 SerialBridge 两种实现。

# 29_前后端效果演示

前端有三个页面：注册页采集掌纹并保存模板，验证页实时识别并显示结果，日志页分页查看历史记录。演示链路从点击验证到最终开锁。

# 30_完整验证流程演示

完整验证流程是：点击验证、抓取 6 帧、选最清晰帧、MediaPipe 检测、ROI 裁剪、预处理、CompCode 编码、模板匹配、阈值判决、开锁。

# 31_效果评估

效果评估指标包括识别成功率百分之九十五以上、平均匹配耗时约 100 毫秒。通过 ROC 曲线和距离分布分析，系统在安全性和通过率之间取得了平衡。

# 32_章节页_不足与总结

最后一部分是不足与总结。系统虽然完成了闭环验证，但在算法和系统层面还有改进空间。

# 33_算法不足

算法方面有四个不足：CompCode 方向编码粒度有限、ROI 对光照敏感、阈值需手动调参、缺乏活体检测。这些是后续优化的方向。

# 34_系统不足

系统方面有四个不足：硬件连接不稳定、单用户串行识别、电磁锁供电安全、摄像头分辨率限制。可以通过加入心跳检测、异步处理等方案改进。

# 35_总结与展望

总结来说，我们完成了从采集到开锁的完整闭环系统，算法层零硬件依赖，硬件抽象层支持快速切换。后续可以引入 CNN 特征、活体检测和嵌入式独立部署。
