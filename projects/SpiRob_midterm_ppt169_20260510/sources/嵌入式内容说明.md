# 对数螺旋软体机器人嵌入式控制部分说明

## 1.项目概述

本项目面向一种仿生对数螺旋软体机器人。机器人主体由若干离散单元串联组成，整体形态参考自然界 中章鱼腕、卷须、象鼻等结构的卷曲规律。机器人通过拉线驱动实现弯曲、伸展、包覆和抓取动作。

当前嵌入式系统的主要任务是控制两路步进电机，分别拉动机器人两侧的驱动线。通过控制两根拉线的 收缩量、放松量、方向和速度，可以组合出不同的机器人姿态和抓取动作。

本阶段代码已经实现了：

两路步进电机使能控制 两路方向信号控制 两路PWM脉冲输出 基于定时器中断的目标脉冲计数停止 角度控制接口 拉线长度控制接口 双电机同步动作接口 四阶段仿生抓取动作流程

## 2.项目原理

机器人本体可以看作一个可卷曲的柔性机构。两根驱动线分别位于机器人两侧，当某一侧拉线收缩时， 该侧长度减小，机器人会向对应方向弯曲或卷曲；当另一侧拉线收缩时，机器人会产生反向弯曲或展开 趋势。

我们将抓取过程分为四个典型阶段：

1. Packing：预卷曲
2. Reaching：伸展接近目标
3. Wrapping：沿物体表面包覆
4. Grasping：收紧完成抓取

## 3.硬件结构

当前系统主要由以下部分组成：

STM32F407控制器 两个步进电机 两个DM422驱动器 两个线轴 两根拉线 对数螺旋软体机器人本体 24V电源

### 3.1引脚分配

当前工程中主要控制引脚如下：

|功能|STM32 引脚|说明|
|---|---|---|
|PUL1|PA0 / TIM2_CH1|1 号电机脉冲|
|DIR1|PC2|1 号电机方向|
|ENA1|PC3|1 号电机使能|
|PUL2|PE9 / TIM1_CH1|2 号电机脉冲|
|DIR2|PG0|2 号电机方向|
|ENA2|PG1|2 号电机使能|

1号电机使用 TIM2_CH1  输出PWM脉冲，2号电机使用 TIM1_CH1  输出PWM脉冲。

## 5.定时器和PWM控制原理

步进驱动器通过 PUL  引脚接收脉冲信号。每收到一个有效脉冲，电机前进一步。PWM的频率决定电机 速度，PWM输出的脉冲个数决定电机转动角度或收线长度。

当前代码中：

#define MOTOR1_PULSE_PER_REV   1600U #define MOTOR2_PULSE_PER_REV   1600U 表示驱动器细分配置为：

1600脉冲/电机一圈 两个定时器都被配置成1 MHz的计数频率，因此可以通过修改自动重装值 ARR  控制PWM频率：

<!-- Page 3 -->

arr = MOTOR_TIMER_FREQ / freq_hz - 1U;

例如，当目标频率为3200 Hz时，电机每秒接收约3200个脉冲。

## 6.拉线长度换算

当前线轴直径设置为5 mm：

#define MOTOR_SPOOL_DIAMETER_CM 0.5f 线轴每转一圈的理论收线长度为：

周长= π ×直径= 3.1415926 × 0.5 cm ≈ 1.5708 cm 因此，拉线长度到电机脉冲数的换算关系为：

steps = cable_cm / spool_circumference_cm * MOTOR_PULSE_PER_REV;

代码中使用：

steps =(uint32_t)(steps_float + 0.5f);

其中 +0.5f  用于四舍五入，避免浮点数直接转整数时总是向下截断。

## 7.动作库设计

当前控制代码不是只写死某一个动作，而是逐步整理成“动作库”的形式。动作库分为三层。

### 7.1底层电机接口

底层接口负责单个电机的基础控制：

Motor1_Enable();

Motor1_Disable();

Motor1_SetDir();

Motor1_SetSpeed_Hz();

Motor1_MoveSteps();

2号电机对应函数为：

Motor2_Enable();

Motor2_Disable();

Motor2_SetDir();

Motor2_SetSpeed_Hz();

Motor2_MoveSteps();

这些函数直接操作GPIO、TIM和PWM。

<!-- Page 4 -->

### 7.2中层运动接口

中层接口把“脉冲数”封装成更容易理解的控制量。

角度控制：

Motor1_MoveAngle(angle_deg,dir,freq_hz);

Motor2_MoveAngle(angle_deg,dir,freq_hz);

拉线长度控制：

Motor1_MoveCableCm(cable_cm,dir,freq_hz);

Motor2_MoveCableCm(cable_cm,dir,freq_hz);

其中：

cable_cm：拉线长度，单位cm dir：方向 freq_hz：PWM频率，对应电机速度 当前方向定义为：

#define MOTOR_DIR_CW   0U #define MOTOR_DIR_CCW  1U 含义为：

MOTOR_DIR_CW：顺时针，收缩拉线 MOTOR_DIR_CCW：逆时针，放松拉线

### 7.3高层组合动作接口

高层接口用于同时控制两个电机，形成机器人动作阶段：

Motors_MoveCableCmTogether( motor1_cable_cm,motor1_dir,motor1_freq_hz, motor2_cable_cm,motor2_dir,motor2_freq_hz );

该函数可以在一个阶段中同时给两个电机下发动作指令。若某个电机不需要运动，则对应长度传入

0. 0f。

等待动作完成的函数为：

Motors_WaitUntilStop();

它会同时检测两个电机的busy状态，直到两个电机都停止后再进入下一阶段。

## 8.当前四阶段动作流程

当前默认任务中实现了一组仿生抓取动作流程。该流程参考论文中的 Packing -> Reaching -> Wrapping -> Grasping  四阶段控制思想。

当前阶段参数如下：

|阶段|1 号电机|2 号电机|目标|
|---|---|---|---|
|阶段 1|顺时针收缩 2.9 cm|不动|预卷曲|
|阶段 2|不动|顺时针收缩 2.5 cm|根部弯曲/伸展|
|阶段 3|逆时针放松 6.0 cm|不动|尾部放松，形成包覆趋势|
|阶段 4|不动|顺时针收缩 4.1 cm|抓取收紧|

代码形式为：

Motors_MoveCableCmTogether(2.9f,MOTOR_DIR_CW,MOTOR_STAGE_SPEED_HZ,

0. 0f,MOTOR_DIR_CW,MOTOR_STAGE_SPEED_HZ);

Motors_WaitUntilStop();

Motors_MoveCableCmTogether(0.0f,MOTOR_DIR_CW,MOTOR_STAGE_SPEED_HZ,

2. 5f,MOTOR_DIR_CW,MOTOR_STAGE_SPEED_HZ);

Motors_WaitUntilStop();

Motors_MoveCableCmTogether(6.0f,MOTOR_DIR_CCW,MOTOR_STAGE_SPEED_QUICK_HZ,

0. 0f,MOTOR_DIR_CW,MOTOR_STAGE_SPEED_HZ);

Motors_WaitUntilStop();

Motors_MoveCableCmTogether(0.0f,MOTOR_DIR_CW,MOTOR_STAGE_SPEED_HZ,

4. 1f,MOTOR_DIR_CW,MOTOR_STAGE_SPEED_HZ);

Motors_WaitUntilStop();

这说明当前动作已经不是单纯控制单个电机，而是以“阶段”为单位同时管理两个电机。某阶段中不参与运 动的电机以 0.0f  长度表示。

## 9.定时器中断停止机制

每个电机运动时，代码会设置目标脉冲数：

motor_target_pulses = steps;

然后启动PWM和对应定时器更新中断。每次定时器更新中断到来时，计数变量加1：

motor_pulse_count++;

当计数达到目标值时，停止PWM：

HAL_TIM_PWM_Stop(...);

<!-- Page 6 -->

1号电机由 TIM2  回调计数停止，2号电机由 TIM1  回调计数停止。这样可以实现两个电机独立计数、 独立停止。

## 10.当前嵌入式部分特点

当前嵌入式控制具有以下特点：

1. 使用PWM脉冲控制步进电机，结构清晰。
2. 电机控制与动作流程已经初步分层。
3. 已经支持双电机同步阶段控制。
4. 动作参数使用厘米作为输入，便于实验调参。
5. 使用FreeRTOS任务组织动作流程，后续可扩展多任务。
6. 当前仍属于开环控制，尚未加入张力、视觉或接触反馈。

## 11.目前存在的问题

当前系统虽然能够执行固定动作流程，但仍存在以下不足：

1. 没有回零流程，每次实验需要手动初始化。
2. 速度控制为固定频率，尚未加入加减速曲线。

## 12.后续嵌入式改进方向

后续可以将动作库继续扩展为更完整的控制框架。

### 12.1增加动作库表驱动

可以用结构体描述一个动作阶段：

typedef struct { float motor1_cm;

uint8_t motor1_dir;

uint32_t motor1_speed;

float motor2_cm;

uint8_t motor2_dir;

uint32_t motor2_speed;

uint32_t delay_ms;

}RobotActionStage;

这样不同动作只需要定义动作表，不必反复修改任务代码。

### 12.2增加回零与预紧

建议增加实验开始前的初始化动作：

放松两根线 人工或传感器确认初始状态 慢速收线到刚好绷紧 将当前位置作为动作零点 这可以显著提高实验重复性。

<!-- Page 7 -->

### 12.3增加视觉与上位机通信

使用摄像头进行自动抓取，可以将系统分为：

上位机：视觉识别、物体定位、抓取决策 下位机：电机动作库执行 上位机通过串口向STM32下发动作命令，例如：

ACTION PACK ACTION REACH ACTION WRAP ACTION GRASP

## 13.中期总结

目前项目的嵌入式部分已经完成了从“单电机PWM驱动”到“双电机动作库控制”的初步搭建。系统能够通 过控制两根拉线的收缩与放松，复现对数螺旋软体机器人抓取过程中的基础动作阶段。

现阶段的控制仍以开环长度控制为主，适合进行结构验证、动作复现和实验参数调试。后续工作重点应 放在动作库构建、收线长度标定、初始状态回零、视觉引导上。通过这些扩展，系统可以从固定动作演 示逐步过渡到自动化、自适应的物体抓取控制。
